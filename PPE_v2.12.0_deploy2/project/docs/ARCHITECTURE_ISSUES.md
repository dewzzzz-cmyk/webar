# Анализ архитектуры и проблем системы моделей

## Текущие проблемы (найденные)

### 1. COCO модели (YOLOv11) НЕ активируются корректно

**Как работает сейчас:**
```
UI: Нажимаем "Активировать" на YOLOv11 Large
  ↓
API: models_router.py → activate_model()
  ↓
Для Ultralytics моделей: создаёт только active_model.json (маркер)
  ↓
Детектор: Проверяет ppe_model.pt → файл НЕ изменился
  ↓
Результат: Детектор продолжает использовать старую модель!
```

**Почему не работает:**
- Ultralytics модели (yolov11n/s/m/l/x.pt) скачиваются автоматически библиотекой
- API НЕ копирует их в `ppe_model.pt`
- Детектор НЕ читает `active_model.json`

### 2. Обученные модели НЕ отображаются в Настройках

**Где хранятся:**
- База данных: таблица `model_versions`
- Файлы: `/app/models/ppe_custom_*.pt`

**Что показывается в UI Настроек:**
- PPE модели (из models_catalog.py)
- COCO модели (YOLOv11 из Ultralytics)
- "Локальная обученная модель" (одна, без списка)

**Что должно быть:**
- Все модели из `model_versions` с метриками mAP

### 3. Кнопка "Начать обучение" не работает

**Что происходит:**
- Frontend вызывает API
- API возвращает 200 OK
- Celery task не запускается / не виден статус

### 4. PPE vs COCO модели - путаница

**PPE модели** детектируют:
- hardhat / no_hardhat
- vest / no_vest
- person

**COCO модели** детектируют:
- person, car, dog, cat (80 классов)
- НЕ детектируют PPE!

**На скриншоте видно:**
- Активна YOLOv11 Large (COCO)
- На мониторинге показывает "person" - это COCO класс
- Нет нарушений PPE - потому что модель не умеет их детектировать!
