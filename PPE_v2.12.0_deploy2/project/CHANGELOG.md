## [2.10.54] - 2026-01-30

### 🚨 КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ

#### Активация моделей теперь РЕАЛЬНО работает
- **ПРОБЛЕМА:** Кнопка "Активировать" модель в UI ничего не делала - модель не переключалась
- **ПРИЧИНА:** API записывал в Redis, но детектор читал только файл `ppe_model.pt`
- **РЕШЕНИЕ:** При активации модель КОПИРУЕТСЯ в `ppe_model.pt`
- **РЕЗУЛЬТАТ:** Детектор подхватывает новую модель через hot reload (до 30 сек)

#### Автоактивация обученных моделей
- **ПРОБЛЕМА:** После обучения модель сохранялась, но не активировалась
- **РЕШЕНИЕ:** Training worker автоматически копирует обученную модель в `ppe_model.pt`
- **РЕЗУЛЬТАТ:** После обучения модель сразу используется для детекции

#### Мониторинг реальной модели детектора
- **ДОБАВЛЕНО:** Детектор публикует в Redis информацию о загруженной модели:
  - `model` - имя файла модели
  - `model_type` - тип (ppe/coco/custom)
  - `classes` - классы модели (JSON)
  - `is_ppe_capable` - может ли детектить СИЗ
- **ПРЕДУПРЕЖДЕНИЕ:** В логах детектора выводится предупреждение если загружена НЕ PPE модель

### ⚠️ ВАЖНО

**Почему детектор показывал только `person`:**
Если в папке models/ есть только COCO модели (yolov8n.pt, yolov11m.pt), детектор загружает их.
COCO модели НЕ умеют детектить СИЗ (каски, жилеты) - только общие объекты!

**Для PPE детекции нужно:**
1. Скачать PPE модель (Настройки → Модели → Hard Hat Detection)
2. ИЛИ обучить свою модель (Обучение → разметить 10+ изобр. → Обучить)
3. Активировать модель (кнопка "Активировать")

- `models_router.py`: activate_model() копирует файл в ppe_model.pt
- `worker.py`: автокопирование обученной модели в ppe_model.pt
- `detector/main.py`: _publish_model_status() публикует инфо о модели
- Hot reload: детектор проверяет mtime ppe_model.pt каждые 30 сек

- **Решение:** Добавлен useEffect для автоматической синхронизации `currentImage` при изменении `images`
- **Улучшено:** Сравнение аннотаций по ID (не только по количеству) - работает для добавления, удаления и замены
- **Результат:** Аннотации теперь сразу появляются на изображении после рисования bbox

#### Очистка кодовой базы

#### Улучшение start.bat
- **Новое:** Пункт меню [F] Fix Containers - исправление конфликтов контейнеров
- **Улучшено:** Автоматическая очистка старых контейнеров при запуске/обновлении
- **Исправлено:** Ошибка "container name already in use" больше не возникает
- **Обновлено:** Версия в заголовке до v2.10.45
- **Удалён:** Дублирующий файл `/dashboard/src/Training.tsx` (1602 строки)
- **Активный:** `/dashboard/src/pages/Training.tsx` (1490 строк) - единственный источник истины

### 📋 Экспертный анализ (v2.10.45)

Проведено расширенное совещание экспертов для диагностики проблемы разметки:

**Выявленная архитектурная проблема:**
```
React Query invalidateQueries → images обновляется ✓
currentImage (useState) → НЕ обновлялся автоматически ✗
Canvas рендерит → currentImage.annotations (пустой/старый) ✗
```

**Применённое решение:**
```javascript
useEffect(() => {
  if (currentImage && images.length > 0) {
    const updatedImage = images.find(img => img.id === currentImage.id);
    if (updatedImage && currentAnnCount !== updatedAnnCount) {
      setCurrentImage(updatedImage);  // Синхронизация!
    }
  }
}, [images, currentImage]);
```
